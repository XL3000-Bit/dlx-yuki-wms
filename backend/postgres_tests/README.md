# PHASE 11.3 独立 PostgreSQL 集成测试

测试代码已编写不代表测试通过。本批未执行数据库连接、迁移或集成测试。

## 独立入口

从项目根目录运行（仅在另行获准运行、隔离核实完成后）：

```powershell
.\backend\.venv\Scripts\python.exe backend\postgres_tests\run.py
```

入口使用标准库 unittest，直接加载本目录中的测试类，不使用 pytest 收集，不加载公共 tests/conftest.py。模块导入不连接、迁移或准备数据；项目依赖在运行防护通过后的测试初始化中加载。测试使用项目迁移产生的 PostgreSQL 结构，不使用 create_all 或 SQLite。

## 实际配置与连接防护

- `PHASE113_PG_DSN`：仅在当前进程环境中提供的专用 PostgreSQL 连接参数。必须显式指定单个 IP 地址、端口、数据库和角色；不回退项目 DATABASE_URL。凭据由用户或管理员在本地提供，不写入仓库、说明、证据或报告。
- `PHASE113_PG_MANIFEST`：经过人工核实的隔离清单 JSON 的绝对路径。清单不含密码或完整连接串。

缺少目标、清单或必需隔离证据，在连接前拒绝。拒绝 DSN 中的 hostaddr、service、servicefile、options，以及影响目标的 PGOPTIONS、PGSERVICE、PGSERVICEFILE、PGHOSTADDR、PGHOST、PGPORT、PGDATABASE、PGUSER 环境变量。连接超时为 5 秒。

清单须包含以下字段：

| 字段 | 内容 |
| --- | --- |
| `identity` | `database`、`role`、`address`、`port`、`database_oid`、`server_version_num`；地址为实际服务器 IP，数字字段为正整数 |
| `migration_revision` | `20260925_0037` |
| `exclusive_database` | true；须有独占测试用途的证据，不能仅勾选确认 |
| `reviewer`、`reviewed_at` | 核实人及核实时间 |
| `evidence` | 下列四项各含非空证据文件的绝对 `path` 和小写 64 位 `sha256` |
| `fixtures` | 下列八个经过核实的合成资料 ID，均为正整数 |

证据类别为 `database_ownership`、`synthetic_fixtures`、`storage_isolation`、`external_effects_disabled`。摘要匹配只证明读取的文件与清单一致，不证明文件内容真实，也不能单独证明隔离。人工审阅必须核实专用数据库所有权及排他用途、无真实业务资料、独立附件与配置位置，以及通知、定时任务和外部接口已禁用或使用测试替代。数据库名称包含 test、本机地址、确认开关均不足以证明隔离。

连接后，入口首先在只读事务中比较实际数据库、角色、服务器地址端口、数据库 OID、服务器版本，并核对 public.alembic_version。全部匹配后才交给测试进行写入。每个新连接重复该校验。目标不匹配立即拒绝；不会自动迁移。测试连接设置有限的查询与锁等待超时。错误报告隐藏 SQL、参数和原始异常细节。

## 合成资料与执行顺序

`fixtures` 的实际键：

- `load_id`：可由允许用户完整访问的测试 Load。
- `no_plan_load_id`：无最终派发计划的测试 Load。
- `legacy_ready_load_id`：用于实际状态接口的 READY Load。
- `outbound_id`、`inventory_allocation_id`：与测试 Load、订单、仓库和客户关系一致的合成订单及库存分配，支持 100 箱／10 托盘的测试表达。
- `allowed_user_id`：启用、仓库与客户范围完整，并具备现有状态接口所需写入角色的专用测试用户。
- `warehouse_denied_user_id`、`customer_denied_user_id`：分别因仓库范围、客户范围不可见的启用合成用户。

三个 Load ID 必须不同。角色使用项目现有接口要求，不修改任何现有业务用户权限；资料准备不属于测试入口的自动初始化。

后续执行顺序：

1. 在本地提供有效认证，另行只读核实实际目标身份、排他使用及四类隔离证据。
2. 获得运行授权后，仅对该专用目标运行项目结构迁移，不运行批量业务种子；确认迁移版本。
3. 仅在隔离目标准备上述最少合成资料，核实真实访问范围和关联关系。禁用真实外部副作用。
4. 完成无凭据清单与证据摘要，设置两个专用进程环境变量。
5. 执行独立入口：先只读核实目标，再进行测试写入。缺表场景仅使用当前事务的 search_path，不删除任何业务表。

## 场景与证据边界

| 场景 | 已编写断言 |
| --- | --- |
| 数量独立约束 | PostgreSQL 数量约束及逐明细超量拒绝；实际预检计算另用明确的内存计划输入检查不跨单位、明细抵消 |
| 分配不可变 | 更新与删除均被数据库拒绝 |
| 定稿不可变 | 只能草稿创建；定稿修改、删除、退回草稿和明细追加、修改、删除均被拒绝 |
| 并发竞争 | 定稿先持锁、明细修改先持锁两种顺序；通过事件和 pg_blocking_pids 确认阻塞，使用有限超时；定稿后修改不得成功 |
| 访问范围 | 实际 HTTP 路由、真实数据库用户及范围；仓库、客户越权和对象不存在返回不泄露详情的相同响应 |
| 缺证据与技术错误 | 无计划、规则和审批证据不得整体就绪；查询失败须返回技术不可用，不能变成 UNKNOWN |
| GET 无副作用 | 请求前后 public 表的持久化行内容、数量以及会话待写集合不变 |
| 原派发行为 | 预检不就绪后，现有 READY → DISPATCHED HTTP 入口仍按原行为执行，不由预检接管 |

HTTP 测试使用真实路由与数据库会话，但以已核实的数据库用户替代认证依赖；不验证 JWT 登录、网络服务部署或真实认证链。行快照不证明序列、外部调用或回滚写尝试均未发生。真实 PostgreSQL 约束、权限查询和并发结果仍须实际运行后才能确认。

## 写入、保留与重复运行

测试会插入合成分配、计划和明细，并尝试应被拒绝的变更。普通事务关闭时回滚；并发场景为跨连接观察而提交的资料保留。状态接口测试会真正派发专用 READY Load，并可能生成项目正常提醒等关联记录；不得用于业务 Load。

测试不自动清理提交的资源，不重置派发状态。重复执行状态测试必须另备专用 READY Load 并更新清单，不能假定上次资料仍可复用。运行后记录保留的测试资料及目标，删除和清理需另行授权。

旧写入口未维护新分配及计划模型。测试表达数量守恒不代表实物退回、库存释放或重复派发流程已经实现或验证；只读预检未接入现有派发阻断。整个 PHASE 11.3 仍未完成。

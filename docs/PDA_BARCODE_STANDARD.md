# PDA 条码编码规范（V1）

## 1. 设计目标

- 扫描一次即可判断对象类型，避免把库位扫成批次或托盘。
- 编码只使用大写字母、数字和短横线，兼容 Code 128、二维码及键盘模拟扫码枪。
- 保留现有 WMS 的入库单、出库单、拣货单和库存批次编号，不破坏历史数据。
- 标签下方必须同时打印人眼可读文本。
- 业务字段存数据库；条码本身不存客户名、数量、货描等会变化的信息。

## 2. 通用规则

1. 字符集：`A-Z`、`0-9`、`-`，录入后统一转大写并去除首尾空格。
2. 日期统一采用仓库业务时区的 `YYMMDD`。
3. 当日流水号左侧补零；编号生成必须由服务器完成，PDA 不自行编流水号。
4. 一张实体标签只表示一个稳定对象；数量变化不重新编码。
5. 内部标签默认使用 **Code 128**。标签空间允许时，可同时印一个内容相同的二维码作为备份。
6. 扫码服务根据当前作业步骤和前缀双重校验；类型不符时禁止提交。

## 3. 编码表

| 对象 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 仓库 | `WH-<仓库简称>` | `WH-LAX1` | 仓库简称 2–8 位，全系统唯一 |
| 库位 | `<仓库简称>-<区域>-<巷道>-<货架>-<层>-<位>` | `LAX1-A-03-12-02-01` | 对应现有 `location_code`；不可因换货而改变 |
| 入库单 | `IB<YYMMDD><4位流水>` | `IB2609020001` | 沿用现有 WMS 规则 |
| 出库单 | `OB<YYMMDD><4位流水>` | `OB2609020001` | 沿用现有 WMS 规则 |
| 拣货单 | `PK<YYMMDD><4位流水>` | `PK2609020001` | 沿用现有 WMS 规则 |
| 库存批次 | `LOT<YYMMDD><4位流水>` | `LOT2609020001` | 沿用现有 WMS 规则；表示逻辑库存批次 |
| 托盘/LPN | `PLT<YYMMDD><6位流水>` | `PLT260902000001` | 新增；每个实体托盘终身唯一，不重复使用 |
| 盘点任务 | `CC<YYMMDD><4位流水>` | `CC2609020001` | 新增；Cycle Count |
| 移库任务 | `MV<YYMMDD><4位流水>` | `MV2609020001` | 新增；库存移动任务 |

## 4. 库位编码

标准库位采用六段式：

`仓库-区域-巷道-货架-层-位`

示例：`LAX1-A-03-12-02-01`

- 仓库：`LAX1`
- 区域：`A`（存储区）；特殊区域使用固定代码
- 巷道：`03`
- 货架/排：`12`
- 层：`02`，由下往上编号
- 位：`01`，按现场统一方向编号

特殊库位保留同样的仓库前缀：

| 区域 | 示例 | 用途 |
|---|---|---|
| 收货暂存 | `LAX1-RCV-01` | 未完成收货/上架 |
| 出库暂存 | `LAX1-STG-01` | 已拣货待复核 |
| 装车月台 | `LAX1-DOCK-01` | 装车交接 |
| 异常区 | `LAX1-EXC-01` | 破损、待查或冻结 |
| 地堆区 | `LAX1-FLR-01-01` | 非货架库存 |

库位标签建议：100 mm × 50 mm；条码内容和下方明文完全相同，并附库位名称。

## 5. 托盘/LPN 规则

`LOT` 与 `PLT` 必须分开：

- `LOT` 是系统库存批次，一个批次可以有多个托盘。
- `PLT` 是现场可搬运的实体托盘，一个托盘同一时间只能属于一个批次和一个库位。
- 拆托、合托必须产生托盘拆分/合并记录；旧托盘码不得分配给另一批货。
- 托盘标签不把数量编码进条码。数量、批次、箱数和状态从服务器实时读取。

托盘标签建议：100 mm × 100 mm，至少显示：LPN、批次号、箱数、客户/货描摘要、当前库位和打印时间。条码只编码 LPN，例如 `PLT260902000001`。

## 6. 五类 PDA 作业中的扫描顺序

| 作业 | 推荐扫描顺序 |
|---|---|
| 入库 | `IB` 入库单 → `PLT` 托盘 → `LOT` 批次确认 → 收货/目标库位 → 数量确认 |
| 出库 | `OB` 出库单 → 出库暂存位 → 逐个 `PLT` 复核 → 月台 → 完成出库 |
| 拣货 | `PK` 拣货单 → 来源库位 → `PLT`（无托盘时扫 `LOT`）→ 数量确认 → 出库暂存位 |
| 盘点 | `CC` 盘点任务 → 库位 → 逐个 `PLT`/`LOT` → 实盘数量 → 提交差异复核 |
| 移库 | `MV` 移库任务（临时移库可省略）→ 来源库位 → `PLT`/`LOT` → 目标库位 → 确认 |

所有库存变更必须由服务器事务完成。重复提交使用“设备 ID + 作业号 + 扫描序号”做幂等校验，避免网络重试造成重复入库、重复扣减或重复移库。

## 7. 扫描校验

- `IB/OB/PK/LOT/PLT/CC/MV` 按前缀识别，长度和日期段必须合法。
- 库位码必须存在于当前选定仓库，且目标库位必须启用。
- PDA 当前步骤只接受预期类型。例如“扫目标库位”时收到 `PLT...` 必须红屏并鸣错音。
- 出库与拣货必须校验托盘属于订单分配的批次；移库必须校验托盘当前确实在来源库位。
- 服务端保存原始扫码值、规范化值、操作员、设备、时间、结果和失败原因，便于审计。

## 8. 实施约束

现有系统可以直接使用 `IB`、`OB`、`PK`、`LOT` 和库位码。上线托盘级扫描、盘点和任务式移库前，需要增加 LPN、盘点任务及移库任务的数据模型和接口。过渡期允许拣货、盘点和移库扫描 `LOT` 后手工确认托盘/箱数量，但不能把 `LOT` 当作永久托盘身份。

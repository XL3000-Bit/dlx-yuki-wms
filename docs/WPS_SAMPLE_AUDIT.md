## 字段和业务规则

| 项目 | 实际样本及现有行为 | 接入要求 |
| --- | --- | --- |
| 柜号、仓点 | OL 均有值；有 2 组相同柜号＋仓点的多条记录 | 不用柜号＋仓点作为唯一键；保留文档、表、记录 ID，区分拆分明细 |
| 客户 | 16 条为单元素数组，4 条为空；现有逻辑直接转字符串 | 单值关联展开后匹配客户；空值和多值单列待处理，不自动归入默认客户 |
| 到仓、拆柜日期 | 各 16 个单元素数组、4 个空值 | 原样传入现有日期解析器会产生 32 个日期字段错误；展开单值后这 32 个日期均可解析 |
| 人工库位 | 14 条有值、6 条为空；包含 `h18,H19`、换行、`D21-8P,D23-1P` 等 | 保留原文；逗号和换行可拆分。带板数写法需独立解析，不能直接自动创建成库位代码 |
| 库位更新时间 | 13 条有值、7 条为空；现有 OL 映射未包含此字段 | 保留来源更新时间；日期精度不足时不能单靠时间判断覆盖，需记录上次同步值并检测冲突 |
| 仓点用途 | 包含 HOLD 5 条、客户自提 1 条、FedEx 1 条，其余为代码形式 | 这些值不应自动作为 Amazon FC 使用；明确目的地类型后再生成 FBA 任务；代码形式也尚未核实有效性 |
| 板数 | 14 条有值、6 条为空 | 区分未填写和实际为 0；现有确认导入会把空板数转成 0 |
| 重量 | 16 条的 lb、kg 均为 0 | 原值保留并提示是否未填写，不能把 0 当作重量已核实；其余重量未对照实物或磅单 |
| FBA、PO | 各 8 条非空：5 条包含两个值、3 条包含一个值 | 保留所有值；不能只取首项，也不能仅凭数组位置推断 FBA 与 PO 的对应关系 |
| 提柜 | 当前 west_coast_4_0 只有 OL、DS、出库三个导入模板 | 提柜需新增柜级计划映射，再与 OL 明细关联；不能把提柜与 OL 各算一遍库存 |

OL 样本汇总：已填板数 82、件数 2,156、体积 172.55。板数有 6 条未填写，这不是完整板数。两批样本无共同柜号，不能将提柜件数与 OL 件数直接做差。尚未核对 YUKI 数据库中的客户、库位及库存余额。

## 历史入库防重候选（2026-09-09）

- `/wps-review` 已增加 OL 明细的只读防重候选检查：优先匹配完整来源身份，否则按去除首尾空格、忽略大小写的柜号查找所有客户、仓库的历史入库记录。同柜记录仅是候选，不能直接认定重复。
- 页面支持按防重状态筛选，展开查看候选入库单、客户、仓库、目的仓、件数、板数和人工库位。候选最多展示 10 条，同时保留完整候选数量；提柜计划表不参与此检查。

下列为后续补齐方向；其中独立 Cargo BOL 与出库关联已完成首轮实现，其他源系统规则仍需核实。

## 页面业务含义

这是一个以集装箱为入口、按每票目的地货物收货的工作台。截图包含 15 行、740 箱、20,633 LB、71.83 CBM。计划箱数、实收箱数、入库托数、仓库库位和估算托数分别展示。Confirm Received 是收货确认入口；标签、BOL、工单和附件服务于后续仓库操作与追溯。

## 已加入 YUKI

入口：入库列表 → 点击柜号，打开 `/inbound/ocean/:id`。

| 原页面要素 | YUKI 实现 |
| --- | --- |
| 按柜、多票货物列表 | 按柜号、仓库、卸货日期汇总，并限制在当前用户权限内 |
| IB Marking / Destination | 唛头、入库单号、客户、目的地展示和筛选 |
| Qty / Weight / CBM | 原计划箱数、重量、体积与汇总 |
| Received Qty / Inbound PLT | 实收箱数、实收托数；先保存草稿，再确认 |
| Whs Area | 选择本仓启用库位，支持批量指定 |
| Markup / EST PLT | 独立手工录入并汇总，不套用未经验证的公式 |
| 批量操作 | 选择货物、按计划填入实收值、批量库位、保存草稿、确认所选货物 |
| Memo / Feedback | 每票备注及反馈；箱数差异必须填写原因 |
| Label / BOL | 收货标签预览、浏览器打印、显示已有 Cargo BOL 编号 |
| Load Type | FBA / FBM |
| WHS File / Admin Document | 按票关联附件；仓库文件保留版本，管理文件可多份并存 |

标签为收货信息标签，未生成承运商条码或外部平台标签。Cargo BOL 为已有货物标识，不等同于运输 BOL 文件。

## 数据与权限

- 草稿记录在 `InboundRecord.source_metadata.ocean_receipt`，保留原有导入元数据。
- 确认后更新实际箱数、托数、库位、收货日期及 Received 状态，并保留计划数量与操作人。
- 批量操作先验证整组数据，再提交。版本号和数据库行锁防止覆盖过期编辑。
- 仅待入库或卸货中、未生成库存的实时记录允许确认；历史导入和已收货记录不可重复确认。
- 确认收货本身不生成库存。上架或完成后的库存生成沿用 YUKI 流程。
- 已确认数量、库位和所属柜次不能通过普通入库编辑绕过锁定；后续状态仍允许进入上架、完成或 HOLD。
- 接口执行仓库、客户及写入角色权限检查，草稿与确认均写入审计日志。
- 原有已收货、已上架或已完成记录显示当前实际箱数及托数；未记录的历史计划量无法追溯还原。

## 边界与后续核对

登录后已核实 Actions 菜单、字段分离与部分 BOL 前置条件；OW、WHS PLT Count 的数据来源、Ready To Ship 的设置规则、WO 联动和估托公式仍未确定。本次未推断这些规则，也未自动把收货记录标记为可发货。发货仍使用 YUKI 已有出库流程。

YUKI 当前缺少独立航次/柜次 ID，因此使用“柜号 + 仓库 + 卸货日期”分组。同一柜在同一天复用或日期为空时，需要先维护准确的卸货日期，避免把不同批次视为同组。页面数据仅来自 YUKI，没有建立与参考系统的同步。

## 2026-09-09 表格式人工收货

- 实收箱数、入库托数、库位、计费托数、预估托数、FBA/FBM、Memo 和 Feedback 支持单元格直接填写。
- Tab / Shift+Tab 跨列，Enter / Shift+Enter 跨行；备注框 Shift+Enter 换行，Ctrl+S 保存草稿。
- 从 WPS/Excel 粘贴矩形数据时，按上述可编辑字段顺序填入；空单元格清空原值，信息展示列不参与粘贴。整批先校验，越界、只读行、非法数字或错误库位均不产生部分修改。
- 库位手工输入并提供候选，必须匹配当前仓库已维护的有效库位；不自动新增库位，不涉及扫码。
- 非法输入保留原文并逐格提示，修正后才能保存。行状态区分未保存、保存中、已保存和失败；保存失败保留草稿，确认收货仍是独立操作。
- 状态筛选固定本次选中的行，填写时不会因状态变化移出视图；切换页签重新筛选。

验证：10 项前端规则测试、7 项 Ocean Inbound 后端测试与 Vite 生产构建通过。本地服务已启动，Chrome 能打开登录页；当前会话未登录，因此本轮未完成登录后的浏览器交互验收。未部署远程环境。
